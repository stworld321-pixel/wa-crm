Version 6.0.0

Released October 2026 · Major reliability, integrations & UX milestone.

New integrations & OAuth

  • Google Workspace OAuth — fully implemented: replaced the "Not available yet" placeholder with a real OAuth popup flow backed by the Lovable App User Connector gateway. The connection dialog opens a popup, exchanges the code server-side, fetches the authenticated email via /oauth2/v2/userinfo, and upserts the token into installed_integrations. Disconnect is clean. Granted scopes: gmail.readonly, gmail.send, drive.readonly, calendar, contacts.readonly. Required env var: GOOGLE_WORKSPACE_APP_USER_CONNECTOR_CLIENT_API_KEY.
  • Social Studio — redirect-URI guidance for TikTok & LinkedIn: the OAuth channel-connection panel now surfaces the exact callback URL (/api/public/social/callback) that must be registered in TikTok Developer Portal and LinkedIn Developer App settings before initiating the OAuth flow, eliminating the most common "redirect_uri mismatch" error for these platforms.

Messaging & inbox fixes

  • Messenger unknown-contact names fixed: inbound Messenger messages no longer appear under a raw UUID. The webhook handler now calls the Graph API (/v21.0/{sender_id}?fields=name) to resolve the sender's display name and falls back to "Messenger user <id>" when the API is unavailable, preventing blank or UUID-labeled conversations in the inbox.
  • Messenger webhook diagnostics — verify-token check: the Meta App status panel now includes a dedicated META_WEBHOOK_VERIFY_TOKEN stored diagnostic row. Administrators can immediately see whether the missing META_WEBHOOK_VERIFY_TOKEN (or legacy MESSENGER_WEBHOOK_VERIFY_TOKEN) environment variable is preventing the webhook subscription challenge from completing, with a step-by-step remedy.
  • WhatsApp template wizard — Submit to Meta always visible: the template editor dialog was reworked from a single scrollable container to a flex flex-col layout with a shrink-0 sticky footer, ensuring the "Submit to Meta" / "Save & resubmit to Meta" button is always reachable regardless of screen height. The button was also renamed from "Save & submit" for clarity. Previously the footer scrolled out of view on any screen shorter than the full form height.
  • Template preview dialog — responsive sizing: the inbox template-preview dialog now applies sm:max-w-4xl max-h-[90vh], preventing overflow on screens narrower than 1280 px.

E-commerce & billing

  • Shopify product sync — 250 products per page: the store-sync server function now uses the Shopify API maximum of 250 products per request (previously hardcoded to 100 for all platforms), reducing round-trips by 60 % for large catalogues. WooCommerce retains 100 (its own REST API maximum). The pagination cursor loop and Link-header parser were already correct and required no change.
  • Billing documents — workspace currency displayed on load: the billing-documents route now reads currency via useTenantCurrency() with a useEffect sync guard instead of a one-shot useState initializer. ZAR, EUR, GBP, and any other non-USD workspace currency now appear correctly on first render without a hard refresh.
  • PDF print — iframe clone approach: the printDocument() helper was rewritten to clone the printable node into a hidden iframe and call contentWindow.print(). The previous window.print() call produced blank pages or unstyled output because the main document's stylesheets were not available in the print context.

Booking & marketing

  • Booking module — Appointments tab opens first: the booking overview defaulted to the "Availability" tab on load. The defaultValue prop is now correctly set to "appointments", matching user expectation that the primary view is the upcoming-appointments list.
  • Drip sequences — Pause / Resume / Activate actions: the drip-sequence panel now renders a SequenceActions component for each row, surfacing contextual per-sequence actions: Pause (running), Resume (paused), and Activate (draft). The previous implementation showed a static placeholder with no controls.

Security & correctness (backend)

  • Webhook workspace scoping — cross-tenant receipt poisoning fixed: processStatusEvent in webhook.server.ts now receives the resolved account object and scopes every message_outbox and messages query to workspace_id. Previously a delivery receipt arriving on one workspace's webhook could update a message row belonging to a different tenant.
  • Filter-injection via .or() fixed: raw string interpolation in the inbound-message deduplication query was replaced with a properly quoted filter, preventing a crafted wamid value from escaping the intended filter and matching arbitrary rows. The inbound duplicate check also now includes workspace_id so cross-workspace false-deduplication is impossible.
  • applyWaMessageStatus cross-workspace protection: the WA status handler in wa-inbox.server.ts now requires an explicit workspaceId parameter and scopes its update query accordingly, preventing a QR-webhook delivery event on workspace A from silently marking a message as "read" in workspace B.
  • Scheduler double-dispatch race fixed: the drip-sequence / scheduled-message processor in scheduler.server.ts was replaced with an atomic UPDATE SET status='processing' RETURNING * claim step. Two concurrent worker instances can no longer both read the same "pending" row and dispatch the same message twice.
  • AI conversation stream — overrideConfig allowlisted: the /api/ai/conversation-stream route previously accepted any key under overrideConfig. It is now restricted to language and tone only; attempts to inject model, tool-call config, or other keys are silently discarded, closing a prompt-injection escalation path.
  • Workflow-queue and analyze.server hooks — supabaseAdmin enforced: two server-side hook handlers (workflow-queue.ts and analyze.server.ts) were constructing a raw Supabase client with the service-role key, bypassing the demo-mode write guard. Both now use the centralised supabaseAdmin singleton so demo instances cannot be written to through these paths.
  • Billing — previewPlanChange auth gate added: plan-change.functions.ts was missing the assertOrgAdmin check. A non-admin workspace member could previously call the preview endpoint and observe pricing data for plans above their current entitlement. The check is now the first operation in the function.
  • Coupon redemption — race condition fixed: the invoice engine replaced a racy read-modify-write (SELECT UPDATE in two round-trips) with a single optimistic conditional UPDATE WHERE remaining_uses > 0 RETURNING *. High-concurrency checkout flows can no longer over-redeem a limited coupon.
  • Sales realtime subscriptions — workspace_id filtered: the use-sales-realtime.ts hook's Supabase Realtime subscriptions on quote_line_items and invoice_line_items lacked a workspace_id filter. Any line-item change anywhere on the platform would trigger UI refreshes for every active sales tab across all tenants. Both subscriptions now carry an explicit workspace_id = eq.<id> filter.

Builder & widget fixes

  • Flow Builder & Chatbot Builder — sidebar auto-collapse: opening the Flow Builder or Chatbot Builder now automatically collapses the main application sidebar, giving the full viewport width to the builder canvas. Closing the builder restores the sidebar to its previous state. Previously the sidebar remained open and overlapped the builder at smaller viewport widths.
  • Live Chat widget — session reuse hardened: the widget runtime now stores visitorKey and session token as separate local-storage keys and validates both independently on page reload. A stale or mismatched token no longer causes the widget to silently fail to reconnect; it starts a fresh session instead. Covered by the full 704-test widget suite.
  • Tenant accent-colour — foreground always white: accentForeground() in accent-color.ts now unconditionally returns #ffffff. Previously the function ran a contrast calculation that could return near-black on mid-tone brand colours (e.g. #D81C20), and a CSS variable injection at runtime would override the static stylesheet's white, making button labels and badge text illegible. Contrast is now maintained by accentStrong() darkening the fill, not by darkening the text.

Demo & onboarding

  • Demo seed data — two realistic workspaces: fresh installations now receive pre-seeded demo data for both built-in accounts. The agent@demo.com workspace ("Wellness Hub") includes 12 conversations and 37 messages across WhatsApp, Messenger, and Live Chat channels with realistic health-and-wellness scenarios. The user@demo.com workspace ("Northbridge Goods") includes 12 conversations and 35 messages covering e-commerce support scenarios. Evaluators and new team members can explore every inbox and CRM feature without needing to generate test traffic.

Developer quality & React correctness

  • Hook scope fixes across 7 files: useZonedDateFormatter and useTenantCurrency calls that were conditionally invoked inside callbacks, event handlers, or nested functions were lifted to unconditional component top-level scope. This eliminates "rendered more hooks than previous render" runtime errors in the booking calendar, billing documents route, and related views, and brings every affected component into compliance with the React Rules of Hooks.
  • Zero TypeScript errors maintained: all changes ship with 0 tsc --noEmit errors. Strict-mode compilation confirmed after each fix.
